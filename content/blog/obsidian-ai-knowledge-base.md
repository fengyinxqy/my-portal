以前试过不少笔记软件，大多停在「收藏了一堆文章，但很少再翻开」的阶段。这次重新用 Obsidian 搭个人知识库，我先把需求收窄到了两件最实际的事：

1. **降低记录门槛**：平时不需要先想好分类、标题和措辞，主要通过和 AI 对话把想法聊清楚，再由 AI 协助整理成笔记或日记落盘。
2. **让知识库成为 AI 的背景上下文**：希望长期记录下来的项目进展、踩坑经历和个人偏好，以后能作为 AI 了解我的背景入口，减少每次开新对话都要从头自我介绍的成本。

下面记录这套知识库目前的目录结构、工作台设计和使用约定。

## 目录结构：按流动路径划分

底层借鉴了 PARA，并结合日常日记和复盘习惯，用数字前缀固定顺序：

```text
知识库/
├─ 00 收集箱/    # 随手记、未分类的零散想法
├─ 10 项目/      # 有明确目标和周期的具体事项
├─ 20 领域/      # 需要长期维护的方向
├─ 30 知识/      # 沉淀下来的通用技术笔记与方法论
├─ 40 资料/      # 听播客、读书等外部参考素材
├─ 50 日记/      # 按日期记录每日重点与过程
├─ 60 复盘/      # 周复盘与阶段性回顾
├─ 90 归档/      # 已结束的历史项目
└─ 99 系统/      # 模板、使用指南与 AI 阅读入口
```

这套结构里有一个很重要的约定：**想法先扔进收集箱，之后再整理**。记笔记时如果还要纠结「该放哪个文件夹、叫什么名字」，大概率最后就懒得记了。

## 首页工作台与「单一数据源」

为了打开 Obsidian 就能看到全局，我把 `首页.md` 做成了一个轻量的工作台仪表盘，核心原则是**不维护重复信息**：

- **快捷入口（QuickAdd）**：顶部放了 4 个常用动作——快速记录（弹窗直达收集箱）、今日日记、新建项目、全局搜索。
- **进行中项目（Dataview 自动汇总）**：每个项目自己的笔记就是进度唯一来源，首页用 Dataview 自动抓取状态为「进行中」的项目、任务完成数、下一条未完成待办以及截止日期。
- **今日聚焦（双向绑定当天日记）**：当天日记里的「今天最重要的事」是每日重点的唯一保存位置，首页只展示前三条并支持勾选双向同步，历史重点留在原日期不覆盖。
- **活动热力图**：按每天新增或修改过的笔记去重统计，从启用那天开始自然累计，不补造历史数据。

首页聚合进行中项目的 Dataview 查询大致长这样：

```sql
TABLE WITHOUT ID
  file.link AS "项目",
  default(filter(file.tasks, (t) => !t.completed)[0].text, "暂无待办") AS "下一步",
  dateformat(file.mtime, "MM-dd") AS "更新"
FROM "10 项目"
WHERE type = "项目" AND status = "进行中"
SORT file.mtime DESC
```

这样一来，平时只需要在具体的项目笔记和当天日记里写内容，首页和各类索引会自动更新，不会出现「改了一处还要同步改三处」的维护负担。

## 给 AI 准备一份「阅读入口」

为了让 AI 在需要时能更快理解我的背景，我在知识库里专门建了一篇《给 AI 的背景与阅读入口》并挂在首页底部：

- 汇总当前正在推进的项目入口、常用目录约定和记录风格。
- 明确「事实边界」：只写有来源支撑的记录，没有整理进来的背景不让 AI 自行脑补。

目前这一步还是手动指定阅读路径，还没有做到跨所有对话自动检索，但比起每次从零口述背景，已经省了不少力气。

## 备份与博客发布边界

本地 Markdown 最大的好处是数据完全掌握在自己手里，但备份和公开边界得提前想清楚：

- **版本管理与备份**：用 Obsidian Git 插件做本地定时自动提交，同时连了一个私有 GitHub 仓库做远程备份（包含笔记、附件和 `.obsidian` 配置目录），远程推送保持手动确认，避免误覆盖。
- **显式标记发布到个人网站**：知识库里既有私人日记、复盘，也有适合对外分享的笔记。我给个人博客写了一个简单的同步脚本，**只有 YAML 属性里明确标了 `publish: true` 的笔记才会被提取发布**，其余内容默认永远留在本地。

## 写在最后

工具本身很容易陷入「一直在折腾配置、没怎么写内容」的陷阱。目前这套基础结构已经够用，接下来的重点不再是继续加插件，而是通过日常使用去验证它到底顺不顺手——记起来是不是足够轻、回看时能不能快速找到、以及和 AI 协作时能不能真的减少重复沟通。
